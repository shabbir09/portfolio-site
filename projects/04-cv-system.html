The problem

Two audiences need two CVs — an ATS-friendly academic CV and a designed founder CV — but maintaining four documents by hand guarantees drift. Shabbir's old downloadable CV proved it: purely academic, a blank second page, and a "studying" status that was simply wrong.

What was built

  • One master content.yaml where every entry is tagged show_on: [academic, founder]
  • build.py (RenderCV + Typst) rendering both ATS CVs, plus a React/Vite build rendering two premium designed PDFs — "Forge" (Founder) and "Scholar" (Academic)
  • A GitHub Actions workflow that rebuilds and republishes everything to GitHub Pages on every edit, behind one permanent link

How it works

  1. Edit one fact, once, in content.yaml.
  2. Push → CI rebuilds all four PDFs + the share page.
  3. Anyone with the link always gets the current version of the right CV.

Proof / outcomes

  • All 4 PDFs verified live at https://shabbir09.github.io/cv/ on 16 Nov 2026.
  • The system caught its own lesson in production: a renderer fix applied locally but not swept into the CI workflow failed the first two GitHub runs — the fix was swept across workflow, README, and build script, and "consistency sweep before delivery" became a standing rule. That rule is built into this portfolio's workflow too.
